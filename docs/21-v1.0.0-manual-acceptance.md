## 4. `v0.13.10 -> v1.0.0` 升级

### 4.1 升级前事实

- [ ] 基线来自不可变 `0.13.10`，而不是当前源码或 `edge`。
- [ ] 从生产维护窗口生成的完整备份恢复到独立 Compose 项目；网络、域名、SMTP 收件人和对象存储写入均与生产隔离。该生产恢复副本只验证真实既有事实，不补造或修改会员数据来满足覆盖清单。
- [ ] 另建一个与生产恢复副本隔离的合成覆盖副本，包含至少 2 位管理员、普通用户、永久用户名别名、公开/隐藏节点、主题、回复、修订、提及、附件、草稿、点赞、收藏、关注、阅读状态、通知、举报、制裁、角色和信任历史；稀有状态、故障注入和破坏性旅程只在该副本执行。

- [ ] `nextbuf doctor` 无阻断错误；Web/Worker 健康且队列清空或状态已解释。

## 5. 账号生命周期与管理员连续性

- [ ] 普通用户申请注销后显示固定截止时间，重复申请不延长，宽限期内可以撤销。

- [ ] 最终注销撤销凭证和 Session，账号不能再登录。
- [ ] 邮箱、Profile、头像、私人草稿/附件和私有互动按 [ADR-0021](./adr/0021-final-account-deletion-and-data-retention.md) 清理；存储失败会持久重试且不阻塞其他用户。

- [ ] 原用户名不能被新用户抢占；墓碑身份不泄漏旧邮箱或私人资料。
- [ ] 墓碑用户名/邮箱只接受精确小写 canonical 值，最终化不能改写 User UUID、UID、`created_at` 或本次 `deletion_attempt_count`，完成后墓碑不可修改或硬删除。
- [ ] 阻塞邮件投递并同时执行到期注销：注销等待目标 EmailDelivery 锁；`sending` 和 `outcome_unknown` 均持久退避，无死锁、并行新 attempt 或迟到回调改写身份数据。

- [ ] 唯一连续性管理员不能被撤销、暂停/封禁、注销或解绑 credential，拒绝有明确错误且无部分写入。

- [ ] 两个并发首次安装请求不会创建两位首管；过期请求被接管后显示重新提交，且不会清除当前请求的 claim。
