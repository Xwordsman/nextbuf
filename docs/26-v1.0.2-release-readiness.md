# `v1.0.2` 性能补丁发布就绪与验收清单

> 本文件是 `v1.0.2` 的范围冻结、性能证据和 GO/NO-GO 合同，不表示尚未完成的 CI、tag、OCI、Release 或生产升级已经成立。公开证据绑定不可变 commit；真实配置、备份和用户数据只保存在受限发布记录。

## 1. 版本边界

`v1.0.2` 只允许不改变公开行为的性能优化：请求内读取去重、查询瘦身、共享布局、局部加载、动态路由预取和客户端初始化收窄。

不得切换 Go、拆分 frontend/backend、替换 Better Auth、增加迁移或配置、修改权限与内容可见性、增加跨请求身份缓存、改变四容器拓扑，或提前实现 `v1.1.0`、金币/能量、插件、交易、支付和开放 API。

## 2. 冻结身份与迁移

- [x] `package.json`、runtime package、Docker build arg、项目常量和示例环境已推进为 `1.0.2`。
- [x] `prisma/migration-baselines/v1.0.2.json` 与 `v1.0.1.json` 为相同顺序和 SHA-256 的 16 条迁移；历史 SQL 未修改。
- [x] GitHub Actions 的直接公开升级基线已推进为已发布 `1.0.1`，独立补丁脚本验证 `1.0.1 -> 1.0.2`。
- [ ] 冻结 commit 有 DCO sign-off，工作区干净且与 `origin/main` 一致。

- [x] 正常 Profile GET 不写库；缺失 Profile 的历史自愈路径仍创建并复读。
- [ ] 真实 PostgreSQL 集成验证公开节点计数一致、隐藏节点不出现在节点/热门侧栏、在线成员为空。
- [ ] 使用同一数据集记录优化前后首页、主题详情、账号页查询数和服务器内部 p50/p95；不得只报告一次最快值。

## 5. 可见性与权限防回归

- [ ] 匿名/普通用户不能从数字主题 URL、metadata、Shell、热门、搜索、附件和互动列表读取隐藏节点主题。
- [ ] 主题作者与有效治理角色保留既有处置读取；暂停、删除或受制裁身份不能借缓存越权。

## 6. 分层性能门槛

必须分开记录，禁止混算：

### `v1.0.1` 生产对照基线

2026-08-07 在尚未升级的生产 `v1.0.1`（commit `681a3bac959808f548e49b51628e15f1b1d98a6a`）采集应用内部对照。宿主机为 6 vCPU、8,310,530,048 bytes 内存、Linux 5.15；采样时数据库包含 36 位用户、7 个节点、14 个主题和 15 个帖子。首页和公开主题 `14` 各预热 1 次，再从宿主机经 `127.0.0.1:3000` 匿名串行请求 20 次，排除 DNS、TLS、Cloudflare 和跨洲线路：

| 路由 | TTFB p50 | TTFB p95 | 完整响应 p50 | 完整响应 p95 |
| --- | ---: | ---: | ---: | ---: |
| `/` | 39.7 ms | 49.0 ms | 67.1 ms | 81.5 ms |
| `/topics/14` | 48.1 ms | 65.1 ms | 81.6 ms | 101.4 ms |

正式 `v1.0.2` 升级后必须在同一宿主机、同一数据集量级、同一路由和相同预热/采样方法下复测；该小数据集结果只用于同机版本对照，不外推为容量上限。

| 层级 | 方法 | 门槛 |
| --- | --- | --- |
| 应用内部 | 服务器回环访问，预热后至少 20 次 | 不劣于 `v1.0.1`；公共页面继续满足既有 p95 ≤ 3000ms |
| 浏览器软导航 | 完成水合后真实 Link 点击，至少 10 次 | 无 document navigation；p95 不劣于基线并立即显示 loading/已预取壳 |
| 公网端到端 | 相同地区分别记录 DNS、TCP、TLS、TTFB、Cloudflare POP | 只作线路观测，不把跨洲延迟归因于应用或用其掩盖应用回归 |

Worker 十秒门槛、队列恢复和健康探针继续继承 [`v0.13.0` Beta 就绪合同](./16-public-beta-readiness.md)。

## 9. 管理员连续性

升级硬门槛始终至少 1 位合格管理员：`admin/site`、active、邮箱已验证、无注销申请/计划、无有效 suspend/ban，且有非空 credential 密码。0 位必须 NO-GO。

正式 Release 默认要求 2 位。`v1.0.1` 的单管理员批准不能自动延伸到 `v1.0.2`；tag 前必须满足其一：

- [ ] 已配置并验证第二位合格管理员；或
- [ ] 项目所有者对 `v1.0.2` 明确重新批准单管理员发布，受限记录保留原话、日期和风险，`administrator_redundancy_missing` 继续作为警告。

## 11. GO/NO-GO

只有第 2–10 节所有适用 Must 完成、P0/P1 为零、管理员条件满足，并且 tag、Release、OCI、`latest` 与生产镜像身份一致，才可记录 `GO`。

以下任一情况必须 `NO-GO`：隐藏内容或权限回归；软导航退化为整页刷新；16 条迁移发生变化；`1.0.1 -> 1.0.2` 连续性/对象验证失败；候选身份不一致；0 位合格管理员；只有 1 位且没有本版本明确批准；生产备份不可验证。
