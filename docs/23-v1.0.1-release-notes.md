# NextBuf `v1.0.1` 发布说明

> 发布前说明：修复和本地验证已经进入候选冻结，正式 tag、OCI Digest、Release 资产与生产升级证据必须在对应流水线和维护窗口完成后才成立。

`v1.0.1` 是首个稳定版之后的兼容补丁。它修复 `v1.0.0` 审计发现的内容可见性、可信 Origin、Worker 启动清理、邀请码计数和发布验证问题，不增加产品功能，不改变四容器部署结构，也不增加数据库迁移。

## 1. 修复内容

- 隐藏节点中的已发布主题不再通过不可变数字地址或页面 metadata 向匿名和普通用户泄漏。有效的主题作者、节点版主、全局版主和站点管理员仍可读取治理所需内容；隐藏节点不接受新的回复、点赞、收藏或关注。
- `AUTH_TRUSTED_ORIGINS` 现在同时作用于 Better Auth 和 NextBuf 自有写接口。配置只接受逗号分隔的精确 HTTP(S) Origin，统一规范化和去重，并拒绝路径、凭据、查询、片段与通配符；生产公网 Origin 必须使用 HTTPS。
- Worker 在数据库、Redis、队列、心跳或调度初始化失败时，会清理已经取得的 BullMQ、Redis、Prisma 与系统队列资源，并把已经建立的心跳标记为停止，使异常容器能够退出并按重启策略恢复。
- Better Auth 已经持久化用户后，即使其 post-commit 审计/邮件 hook 或后续邀请码消费审计失败，也不会错误退回邀请码次数；只有明确确认用户未创建时才尝试补偿，提交状态无法确认时保守保留次数。

## 2. 发布与升级验证

- 日常主线和发布演练的升级基线从最后一个 Beta 提升为正式 `v1.0.0`，直接验证 `1.0.0 -> 1.0.1`。
- Release body 冒烟测试改为读取当前包版本，确保每个补丁版本在正式标签前就具有唯一且可发布的版本说明。
- `v1.0.1` 冻结清单继续包含与 `v1.0.0` 完全相同的 16 条迁移及 SHA-256；历史 SQL 和 checksum 未改变。
- 主应用和 standalone runtime 的生产依赖审计均无已知漏洞。

## 3. 兼容性

- 数据库：PostgreSQL 16 条迁移保持不变，升级不执行新 DDL，也不重写业务数据。
- 缓存与队列：Redis 数据不是事实来源；Web 与 Worker 必须使用同一版本镜像共同升级。
- 配置：既有单域名部署无需增加变量。使用 `AUTH_TRUSTED_ORIGINS` 的实例必须填写精确 Origin；不再接受 Better Auth 通配符语法。
- 部署：继续使用 `nextbuf`、`nextbuf-worker`、`nextbuf-postgres`、`nextbuf-redis` 四个常驻容器，宝塔单文件 Compose 继续跟随 `latest`。
- 许可：页面必须保留 LICENSE 和 NOTICE 要求的可见 `Powered by NextBuf` 链接。

## 4. 升级方法

`v1.0.0` 是本补丁的直接升级基线。生产升级必须先创建并校验一致性备份，再拉取完整发布镜像并重建 Web 与 Worker：

```bash
./nextbufctl backup
./nextbufctl upgrade 1.0.1 --verify-objects
./nextbufctl doctor
```

宝塔单文件部署使用 Release 中的 `nextbufctl backup --baota <实际编排文件>` 生成归档；核对备份后在面板拉取更新后的 `latest` 并重建。S3 存储还需要同一维护窗口的 Provider 快照或版本记录。不要删除 PostgreSQL、Redis 或附件卷。

## 5. 回退与恢复

若迁移前的拉取或预检失败，可以保持 `v1.0.0` 镜像和原数据继续运行。目标 setup 已启动后若版本、迁移清单、连续性比较、附件对象校验或 Doctor 失败，应保持 Web/Worker 停止，并恢复升级前的 PostgreSQL、附件/Provider、配置和匹配镜像整套备份；不能只把镜像标签改回旧版本。

## 6. 已知限制

- 当前生产实例暂时只有一位合格管理员；`administrator_redundancy_missing` 警告继续保留。既有豁免只绑定已经完成的 `v1.0.0` 发布，`v1.0.1` 正式 GO 前必须增加第二位合格管理员，或由项目所有者对本次发布重新明确接受风险；合格管理员为 0 时始终硬阻断。
- 在线成员跟踪仍未实现，界面保持明确空状态，不生成演示在线用户。
- V1 不包含金币/能量、插件、交易、支付或开放 API；这些内容不属于补丁版本。

## 7. 发布产物与证据

正式标签流水线从冻结候选生成本节，绑定 tag、commit、OCI index、amd64/arm64 Digest、Linux x64 归档、SHA-256、Source SBOM 和 Actions Run。
