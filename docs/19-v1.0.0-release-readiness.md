### 1.2 最终候选冻结与证据位置

最终候选不能通过“提交一份写有自身 commit 或 Digest 的文档”确定，因为该提交会再次改变 commit、镜像配置和 Digest。发布负责人必须采用以下无自引用流程：

1. 完成所有源码、配置和发布文档修改，推送最后一个候选提交。
2. 等待该提交的主线 CI 全部成功，并确认不可变 `sha-<完整提交>` 双架构镜像已发布。
3. 对该 commit 运行 `release_rehearsal=true`，确认深度门槛、run-scoped staging OCI index、Linux x64 归档和 Source SBOM artifact 全部成功，且未创建 SemVer、GitHub Release、完成回执或 `latest`。
4. 在仓库外的加密受限验收目录记录完整 commit、主线/演练 CI URL、OCI/amd64/arm64 Digest、归档 SHA-256、运行时间和人工证据；公开摘要不得包含真实会员标识、邮件、正文、对象键、凭据或配置。
5. 全新安装和真实 Beta 隔离副本验收只使用该不可变候选；未公开 SemVer 时，按[运行手册](./13-installation-operations-runbook.md#未公开-semver-候选的隔离-registry)把基线与候选完整 OCI index 从已记录 Digest 复制到 loopback Registry 并核对复制前后 Digest，不能只创建本地 tag 或忽略 pull。验收过程中不再提交源码变更；发现代码或文档缺陷时，产生新提交并从第 1 步重新开始。
6. 全部签署为 GO 后，在同一 commit 创建不可变 `v1.0.0` 标签。标签流水线复用并重新验证同一 `sha-*` 候选，SemVer OCI index Digest 必须与签署候选相同；Release 完成回执、归档 SHA-256、SBOM 和 provenance 共同形成公开最终身份。发布后的 `main` 文档提交可以补记结果，但不得移动标签。

## 4. 身份、注销与管理员连续性

- [ ] Better Auth 继续拥有密码、Session、验证、OAuth 和 Cookie 行为；没有平行认证实现。
- [ ] Better Auth 通用 `/update-user` 不能绕过 NextBuf 的昵称、头像、Profile、用户名冷却和永久别名管线；认证集成测试确认拒绝后 User/Profile/Alias 与头像对象均不变。

- [ ] 注销后账号不可登录；邮箱、凭证、Session、私人资料/草稿/附件和私有互动按 [ADR-0021](./adr/0021-final-account-deletion-and-data-retention.md) 清理。

- [ ] 注销任务重复执行幂等，单个对象存储故障不会永久阻塞其他到期请求。
- [ ] 大账号注销使用集合式 SQL，不把附件、私人内容或邮件 UUID 无界载入 Node.js；集成夹具至少覆盖 256 组事实。轮换 `AUTH_SECRET` 后，当前与全部历史用户浏览哈希被删除，匿名及其他用户哈希不受影响；历史密钥恢复与安全移除条件按 ADR-0011/0021 验证。

## 10. 发布顺序

1. 冻结功能和迁移，完成上面所有候选门槛。
2. 在独立变更中把版本提升为 `1.0.0`，同步 Dockerfile、示例和文档；主线完整 CI 通过。
3. 复核已启用的 GitHub Repository Ruleset `20172767` 仍保护 `refs/tags/v*` 的创建、更新和删除，并且仅保留发布负责人 bypass。
4. 从该 commit 创建带签名说明的不可变 `v1.0.0` 标签；禁止移动标签。
5. 标签流水线构建并验证精确 SemVer 镜像、归档、校验和、SBOM/provenance。
6. GitHub Release 和全部资产成功后，当前标签在共享锁外写入并远端验证完成回执。
7. 后续共享锁任务重新选择全局最高完整稳定 Release，复核回执、资产、SemVer 镜像和现有通道后，才把回执绑定的 manifest 调和为 `latest`。
8. 核对公开 Digest、归档 SHA-256、Release 状态和 `latest == 1.0.0`，填写本文件第 1 节。
9. 在真实部署执行发布后冒烟并观察 Web、Worker、数据库、队列、邮件和存储；严重异常按备份恢复边界处理并发布更高补丁，不移动已有 SemVer。

## 11. 发布阻断级别

- **P0**：已确认利用、数据不可恢复损坏、错误公开私人数据、发布产物身份冲突。必须阻断。
- **P1**：默认安装/升级失败、核心认证或发帖链路不可用、管理员连续性失效、备份无法恢复。必须阻断。
- **P2**：有可行规避且不损害数据/安全的局部回归。必须在发布说明列出负责人和补丁计划，由发布负责人明确接受。
- **P3**：文案、低影响视觉或后续增强。可进入后续版本，但不得借机扩大 `v1.0.0` 范围。
