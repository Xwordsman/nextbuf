# NextBuf `v1.0.2` 发布说明

> 候选说明：`v1.0.2` 正在按性能补丁范围开发和验证。正式 tag、OCI Digest、Release 资产、`latest` 与生产升级证据只有在对应流水线和维护窗口完成后才成立。

`v1.0.2` 是基于已发布 `v1.0.1` 的向后兼容性能补丁。它优化首页、主题详情和账号设置之间的导航反馈、服务端查询及客户端初始化，不增加产品功能，不改变公开数据、权限、四容器部署或 Better Auth 所有权，也不增加数据库迁移。

## 1. 用户可见改进

- 首页进入主题详情、主题进入账号设置时使用 Next.js 客户端软导航；新增局部加载骨架，动态路由在等待服务端响应时立即显示与现有布局一致的反馈。
- 主题详情加载保持 1380px、230px/300px 和 16px 间距的三栏合同，但不再为了左右栏读取整份首页主题流。
- 账号区域使用持久化共享 layout；资料、账号安全、信任、通知、主题、收藏、关注和参与页面之间切换时不再重建公共导航与外层容器。
- 账户头像菜单在悬停、聚焦或按下时预取账号中心和安全页的动态路由壳。
- 加载动画尊重 `prefers-reduced-motion`，屏幕阅读器获得明确的忙碌状态与加载文本。

## 2. 服务端与客户端优化

- Better Auth Session 改为请求内单例读取；根布局、主题和全部账号页面复用同一次请求中的身份结果，不引入跨请求身份缓存。
- 站点设置在同一请求内去重，根布局中的账号和站点配置并行加载。
- 社区查询拆分为主题流与轻量三栏 Shell。主题详情只读取公开节点计数、社区概览和热门侧栏，不再执行首页分页主题查询。
- 首页总主题数直接汇总公开节点的受约束计数，移除重复的全站主题 count 查询。
- 已存在 Profile 的账号资料 GET 只读一次，不再执行无意义 `upsert`；只有历史缺失 Profile 时才执行一次自愈并复读。
- 首页的静态节点栏和社区侧栏改由服务端渲染，客户端仅接管搜索、筛选、分页和移动端面板，主题详情不再携带完整首页客户端组件。

## 3. 性能结论与测量边界

优化前诊断在生产服务器内部测得首页约 50–100ms、主题详情约 50–150ms、账号页约 35–60ms，说明 Node.js/Next.js 服务端不是公网慢访问的主要来源。公网请求经 Cloudflare LAX 时，端到端 TTFB 约 0.9–2.9 秒；该跨洲 TLS/路由延迟必须与应用内部耗时分开评估，改用 Go 也不会消除它。

候选必须在同一环境分别记录：

1. 应用服务器内部响应与数据库查询；
2. 完成水合后的浏览器客户端导航；
3. 包含 Cloudflare POP、TLS 和公网路由的端到端访问。

正式结论以 [`v1.0.2` 发布就绪清单](./26-v1.0.2-release-readiness.md)绑定的同一候选 commit 和 CI/生产复测证据为准。

## 4. 安全与行为兼容

- Session、角色、制裁、隐私、互动状态和写权限只做请求内去重，不进入跨请求共享缓存。
- 隐藏节点和不可公开主题不能通过 Shell、热门列表、metadata、搜索、附件或个人列表泄漏。
- PostgreSQL 继续是事实源；Redis 可重建；Worker、Outbox、邮件和任务调度合同不变。
- 在线成员仍为明确空状态，不制造演示活动。
- Web 与 Worker 继续使用同一镜像，生产仍只有 `nextbuf`、`nextbuf-worker`、`nextbuf-postgres`、`nextbuf-redis` 四个常驻容器。
- 页面继续保留 LICENSE 和 NOTICE 要求的可见 `Powered by NextBuf` 链接。

## 5. 数据库、配置与升级

- `prisma/migration-baselines/v1.0.2.json` 与 `v1.0.1.json` 保持相同顺序和 SHA-256 的 16 条迁移；升级不执行新 DDL，不重写业务数据。
- 不增加、删除或改变环境变量语义；既有 `v1.0.1` Compose 和 Provider 配置可直接使用。
- 直接升级基线是 `v1.0.1`。正式升级前必须创建并校验一致性备份：

```bash
./nextbufctl backup
./nextbufctl upgrade 1.0.2 --verify-objects
./nextbufctl doctor
```

宝塔单文件部署在 Release 完整、`latest` 已与 `1.0.2` 相同后拉取并重建 Web/Worker。不要删除 PostgreSQL、Redis 或附件卷；S3 存储还需要同一维护窗口的 Provider 快照或版本记录。

## 6. 已知限制

- Cloudflare POP、主机商网络和用户所在地区仍决定公网 RTT/TLS 延迟；本补丁改善应用工作量和页面反馈，不承诺消除跨洲网络延迟。
- 当前生产实例暂时只有一位合格管理员。此前对 `v1.0.1` 的豁免不能自动延伸到本版本；`v1.0.2` 正式 tag 前必须增加第二位合格管理员，或由项目所有者重新明确接受风险。0 位合格管理员始终硬阻断。
- 在线成员、金币/能量、插件、交易、支付和开放 API 不属于本补丁。

## 7. 发布产物与证据

正式标签流水线使用冻结 commit、OCI index、amd64/arm64 Digest、Linux x64 归档、SHA-256、Source SBOM 和 Actions Run 替换本节；候选阶段不写入尚未生成的身份。

## 8. 回退

若拉取或预检在 setup 前失败，可继续运行 `v1.0.1`。目标 setup 已启动后若版本、迁移清单、连续性比较、附件对象校验、登录或 Doctor 失败，应保持 Web/Worker 停止，并恢复升级前 PostgreSQL、附件/Provider、配置与匹配镜像的整套备份；不能只把镜像标签改回旧版本。
